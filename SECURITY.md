# Security policy

Do not place tokens, cookies, credentials, private keys, local paths, private
model receipts, unpublished reviewer identities, or personal screenshots in
this repository. Security reports should use an owner-approved private
channel, never a public issue containing sensitive material.

The verification workflow installs no dependencies and uses only tools
available on the runner. Any future TeX or Lean dependency must be pinned and
reviewed before activation.

Mathematical objections are not software vulnerabilities; record them as
proof-audit reports with the exact artifact hash and first invalid inference.
